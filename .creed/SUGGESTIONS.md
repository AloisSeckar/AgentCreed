# Suggestions

- When instruction text is moved, merged or reworded, rules can be weakened without anyone noticing (e.g. "make sure X" became "if X then..."). Consider adding an "Instruction maintenance" section to `creed-dev`: before applying, list each old rule with its new wording and mark it kept / merged / strengthened / weakened / dropped. Move text word for word by default and keep the strength words (MUST, ALWAYS, make sure, pause). Get user approval for anything not kept.
- `creed-check` skill: 1.3 appends claims from files linked by `ARCHITECTURE.md` to `security-boundaries` instead of `documented-facts` (copy-paste error).
- `creed-check` skill: "project root" and `creed-files` are undefined for nested instruction files (e.g. is `src/AGENTS.md` a `creed-file` to skip, or a linked file to read?). Only explicit links are followed, so files referenced by name (e.g. `creed-dev` skill, `README.md`) are never checked.
- `creed-check` skill: the description promises checking "relevance and accuracy of the documentation", but no step verifies `documented-facts` against the code. Stale versions in `ARCHITECTURE.md` were found only outside the process.
- `creed-check` skill: handling of unclear items is inconsistent (`questions` list for boundaries/instructions vs. "ask the user at the end of chapter 2" for facts and contradictions). Instruction-vs-fact contradictions are not added to `questions`, so the stop condition can miss them. There is no rule for items that belong to `BACKLOG.md`/`SUGGESTIONS.md` (e.g. a TODO inside `ARCHITECTURE.md`), and the order of "ask user" vs. "start over if `fixes` non-empty" is unclear. `fixes` is never reset, so the loop as written never ends.
- `creed-check` skill: no check of `security-boundaries` against `documented-facts`, and no guidance on editing `creed-files` that are templates shipped to other projects (as in this repo's `src/`).
- `creed-check` skill: typos "Strt", "assesment", "fullfilled", "gathered fact".
- `src/AGENTS.md` and `creed-dev` skill duplicate rules: "respect `SECURITY.md`", "respect `ARCHITECTURE.md` and notify about implied changes", "log ambiguities into `SUGGESTIONS.md` and stop if it affects the task". Keep each rule in one place.
