# Suggestions

- `update` replaces the span from the first to the last marker, so user text between several managed blocks is dropped. `setup` instead removes only the blocks and keeps intervening text. Consider aligning the two.
- `setup.js` and `update.js` duplicate the `.creed/version` write and the template download-to-temp-dir logic; a shared helper would remove the duplication.
- `test/update.test.js` duplicates the fixture from `test/setup.test.js`; extracting a shared test helper would reduce drift.
- RESOLVED: `src/AGENTS.md` presents `ARCHITECTURE.md` only as reference material ("to understand tech-stack..."), yet its `## General instructions` contains binding rules, including updating the file after code changes. Agents don't see that section unless they follow two links and read the whole file, so they may skip or skim it. Either state in `src/AGENTS.md` that the section contains mandatory rules, or move those rules into `src/AGENTS.md` and keep `ARCHITECTURE.md` purely descriptive. The same applies to `src/SECURITY.md`; the meta-rules of both files largely duplicate each other and partly duplicate `creed-dev`.
- RESOLVED: `src/SECURITY.md` intro line is missing a verb: "This file security boundaries..." should read "This file describes security boundaries...".
- `README.md` "Setup behavior" lists only `creed-dev` and `creed-chat` skills; `creed-scan` (in `CREED_SKILLS`) is missing.
- When instruction text is moved, merged or reworded, rules can be weakened without anyone noticing (e.g. "make sure X" became "if X then..."). Consider adding an "Instruction maintenance" section to `creed-dev`: before applying, list each old rule with its new wording and mark it kept / merged / strengthened / weakened / dropped. Move text word for word by default and keep the strength words (MUST, ALWAYS, make sure, pause). Get user approval for anything not kept.
